# Claude에게 전달할 사업 구조 검토 프롬프트

아래 내용을 Claude에 그대로 전달하면 된다. 보고서는 `codex/reduce-sync-usage` 브랜치에 있다. 다른 체크아웃에서 작업한다면 먼저 해당 브랜치의 문서를 읽을 수 있는지 확인하고, 기존 미커밋 작업을 덮어쓰거나 main에 병합하지 않는다.

---

우리 육아앱의 운영비와 수익 구조를 함께 검토해줘. Codex가 작성한 보고서를 그대로 승인하는 대신 공식 근거와 계산을 비판적으로 검토하고, 내가 판단하기 쉬운 한국어로 설명해줘.

먼저 다음 문서를 순서대로 읽어줘.

1. `reports/육아앱 운영비와 수익 구조.md` — 이번 조사 보고서. 최신 목표와 최종 비교 계산의 기준.
2. `docs/PRODUCT_BUSINESS_DISCUSSION.md` — 사용자와 Codex의 대화 요약. 확정 요구와 미확정 제안을 구분해둠.
3. `docs/CLAUDE_SYNC_HANDOFF.md` — 현재 구현, 미배포 개선, 호환성 및 실기기 미검증 항목.
4. 필요하면 `research_notes/육아앱 운영비와 수익 구조/`의 구조·수익·신뢰성 조사 메모와 공식 출처.

반드시 유지할 제품 요구는 **‘외부에서도 배우자와 기록이 공유되고 홈 화면 위젯이 자동 갱신된다’**야. 같은 와이파이에서만 동기화하거나 앱을 열어야만 최신화하는 방식으로 요구를 줄이지 마. 다만 모바일 OS 제약에 따른 푸시 지연·누락은 현실적으로 다루고, 복구·최신 여부 표시를 설계해야 해. 현재 아이폰은 Safari/PWA이고, iOS 네이티브 위젯을 이미 구현한 것으로 보면 안 돼.

사업 목표는 **월 최소 10만원, 기대 목표 월 20만~30만원**이야. 매출보다 실제로 남는 돈이 중요해. Apple 개발자 연 99달러 외에 월 서버 지출이 없는 방식과, 소액 월 지출을 허용하는 방식을 비교하고 싶어. Apple 99달러는 매년이고, Google Play 등록비·스토어 수수료·광고 정산 지연도 구분해서 봐줘.

검토할 쟁점은 다음과 같아.

- 무료 Firestore + Workers/D1 + FCM으로 어디까지 운영할 수 있고, 어느 지점에서 제한·중단 위험이 생기는가? 무료 한도는 모든 가족이 공유하고, 과거 기록의 저장량도 계속 누적돼.
- Cloudflare만 유료화하면 Firestore Spark 한도는 그대로야. 기존 개선형, Firebase 통합, Cloudflare 중심 통합 중 전체 비용·개발 부담·데이터 이전 위험을 비교해줘. Cloudflare는 필수가 아니지만, 없애는 것 자체를 목표로 하지는 마.
- 월 서버 예산 0원·1만원·3만원·5만원에서 월 10만·20만·30만원을 남기려면 어떤 사용자·수익 조합이 필요한가? 공식 가격과 실제 사용량이 없으면 추정과 확인 사실을 구분해줘.
- 월 2,900원 가족 구독, 유료 전환율 3~5%, 광고 eCPM 500~2,000원은 **가정**이고 아직 확정하지 않았어. 광고·구독 혼합이 적절한지, 무료 삐요로그와 비교해 결제할 이유가 있는지 검토해줘.
- 광고를 보는 개인 DAU, 서버 비용을 만드는 일간 활동 가족, 구독 전환의 모집단인 월간 활동 가족을 혼동하지 마. 위젯만 보는 사용자는 앱 광고 노출을 만들지 않고, 광고 제거 구독자는 광고 매출에서 제외해야 해. 현재 PWA 사용자를 네이티브 AdMob 수익으로 계산하지 마.
- 보고서는 예시 환율 1달러=1,500원, Apple 연회비 월 환산 12,375원, 구독 정산 비교모형 `2,900÷1.1×0.85`를 사용했어. 실제 세무·정산 확정액이 아니며, 소득세·본인 인건비·환불·고객 획득비는 제외했어. 서울 Firestore 단가와 실서비스 사용량도 아직 확정하지 못했으니 근거 없는 정밀 견적을 만들지 마.
- 기존 보고서의 주기 조회 제거 개선을 무조건 신뢰성 향상으로 평가하지 마. 잠금·절전·푸시 누락·동시 입력·구버전 APK 혼용의 실제 검증과 복구 경로를 함께 봐줘.

최종 답변은 쉬운 결론, 무료안과 유료안 비교, 월 10만·20만·30만원 목표표, 가장 위험한 미검증 가정, 다음에 실제로 측정할 항목 순서로 정리해줘. 반론이나 계산 오류가 있으면 근거와 수정값을 알려줘. 보고서 내용을 수정·추가한다면 기존 확정 요구와 변경 이유를 보존해줘.

**이번 요청은 조사·검토야. 계정 생성, 결제수단 등록, 요금제 변경, 광고/결제 SDK 구현, 서버 배포, main 병합, 기존 기록 삭제·이관을 승인하는 요청은 아니야.**
