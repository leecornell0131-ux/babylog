# 실시간 공유 사용량 개선 설계·작업계획 (2026-10-20)

사용자가 검토 보고서를 읽고 구현을 요청했다. 기존 서비스는 매일 실제 육아에 사용 중이며 중단하면 안 된다. 아이폰은 Safari/PWA, 배우자는 구버전 Android APK다.

## 범위와 적용 원칙

- 기준 main `48e3a874e4514e92b397e1fe5c617373b7902b82`, 복구 태그 `backup/main-before-sync-optimization-2026-10-20`.
- 작업 브랜치 `codex/reduce-sync-usage`. 기존 별도 분석 체크아웃을 재사용한다.
- 앱 저장소 babylog-v1/BabyApp/BabySync.local/end:null, Firestore 사건/삭제/커서 형식 유지. 최근 이틀만 남기는 변경 및 Firestore 캐시 전환은 이번 범위에서 제외.
- 서버 URL/요약/FCM 계약 유지. D1 바인딩이 없으면 기존 KV로 동작; 바인딩이 있으면 요약만 D1, 토큰은 KV. 옛 KV 요약은 최초 조회/저장 시 fallback으로 읽고 삭제하지 않는다. D1 오류 시 KV에 새 값을 몰래 쓰는 fallback은 금지(분산된 최신값 문제).
- D1 최신행 저장은 at 조건을 SQL에서 검사해 동시 요청의 역순 덮어쓰기를 방지. 동일 at 재시도는 허용(FCM 실패 후 재시도 때문).
- 웹은 의미 있는 위젯 필드(at 제외) 비교, 성공 후에만 완료 표시. 최근 전송 실패 요약을 별도 로컬 키에 보관, 온라인/화면 복귀 때 복구. 상대 기록 수신 시 비교 상태 무효화해 이전 내용으로 되돌리는 저장도 전송한다.
- Firestore 여러 배치가 모두 성공한 후 notify 1회. 부분 실패 시 미저장 내용을 위젯에 알리지 않음.
- 새 Android는 기존 7101 정기 job을 취소. FCM과 앱 실행 시 Firestore의 기존 실시간 리스너 복구를 유지. 구버전에는 기존 summary API 제공. 위젯 자체의 로컬 시계 갱신은 유지.
- 이 브랜치는 main에 병합/실서버 배포하지 않는다. 브랜치 APK 빌드는 배포가 아닌 artifact로만 남기는 기존 정책 유지. 사용자 확인 후 전환할 수 있게 절차와 복구 한계를 기록한다.

## 실행 순서와 검증

- [ ] 서버: node:test + node:sqlite로 실제 SQL 역순/동시 저장, KV 이관, 옛 API, D1 장애, CORS 테스트를 먼저 실패시킨 뒤 구현.
- [ ] 웹: 의존성을 주입한 전송 큐로 의미 동일/변경, 실패/재시작, 가족 전환, 상대 변경, 전송 중 다음 저장을 먼저 검증한 뒤 구현.
- [ ] sync: 여러 배치 완료 후 1알림·실패 시 없음, 기존 local-only/수신 무반복/기록 형식 회귀 확인.
- [ ] Android: 정기 job 취소, 앱/위젯 기존 경로 유지. 가능한 빌드/정적검사와 실기기 미검증을 분리.
- [ ] 배포 workflow: D1 자동 준비/마이그레이션 후 Worker 배포. 원격 실행은 하지 않음. 로컬 D1 통합 검증과 workflow 구문 검증.
- [ ] GitHub 작업 브랜치와 PR에 테스트 결과, 적용 안 됨, 오늘/내일 비교법 및 롤백을 인계.
